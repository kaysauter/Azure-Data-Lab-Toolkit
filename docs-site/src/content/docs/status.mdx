## Target order

The order is deliberate. A later target should reuse tested core behavior instead of creating a parallel toolkit.

1. **SQL Server on Azure VM** - first end-to-end implementation and test target.
2. **Azure SQL Database** - first managed SQL target.
3. **Azure SQL Managed Instance** - managed instance networking and migration scenarios.
4. **Microsoft Fabric** - workspace and item creation plus guided target decisions.
5. **Azure Database for PostgreSQL** - managed PostgreSQL scenarios.
6. **SQL Server and PostgreSQL on Linux VMs and containers** - portable engine scenarios.
7. **Kubernetes** - deferred until container and lifecycle contracts are mature.

Azure Databricks, Git providers, storage providers, community tools, and additional data services are tracked as supporting or future providers in the [Roadmap](../roadmap/).

## Release truth

Published releases and their release notes will be the source of truth for available behavior. Architecture documents describe intent; issues and project boards describe planned work; neither is a delivery commitment.
