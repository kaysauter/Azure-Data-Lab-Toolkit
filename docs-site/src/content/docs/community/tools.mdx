## Catalog contract

Every future integration must record:

- canonical project and download sources;
- owner, license, attribution, and redistribution rules;
- supported platforms and target providers;
- pinned version and update policy;
- checksum or signature, with user-supplied checksum support;
- required privileges and network access;
- silent-install capability and arguments;
- verification and uninstall behavior.

Private or internal software may be supplied through an approved local path or URL. The same checksum, provenance, secret, and report-redaction requirements apply.

## Solution packs

A solution pack will combine data, tools, configuration, probes, and learning outcomes around one reproducible scenario. It must reference catalog records rather than hide ad hoc downloads inside scripts.

Maintainers are invited to propose a showcase scenario through [Suggest A Project](../suggest-a-project/).
