The data catalog will treat ownership, license, provenance, sensitivity, compatibility, size, and restore method as first-class metadata.

These are candidates, not bundled datasets. Each integration needs a license and redistribution review. A database package and the underlying data can have different owners and terms.

## User-provided data

Planned source types include:

- local files and directories;
- approved HTTPS URLs;
- Azure Blob Storage, ADLS Gen2, and Azure Files;
- existing databases or backups;
- generated and synthetic data;
- private catalog entries.

Real data must require an explicit sensitive-data acknowledgement and policy validation. Credentials belong in Key Vault or an equivalent approved secret store, not in YAML.

## Restore and import

Restore methods depend on the target and artifact: native backup restore, URL restore, scripts, bulk load, logical dump, import APIs, shortcuts, or generated data. The catalog must preserve checksums and source-relative metadata so evidence can show exactly what was loaded.

Migration mechanisms such as BACPAC are deferred and must not be described as assessment.
