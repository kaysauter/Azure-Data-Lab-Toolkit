<span class="status status-planned">Community intake</span>

The planned catalog should help maintainers showcase useful tools and databases through reproducible, credited lab scenarios. Open-source, commercial, private, and internal projects can all be considered when their terms and delivery model are clear.

## Send a suggestion

- Message [Kay Sauter on LinkedIn](https://www.linkedin.com/in/kaysauter/).
- Use the [Kay On Data contact form](https://www.kayondata.com/contact/).
- For a fully formed public proposal, open a [GitHub issue](https://github.com/kaysauter/Azure-Data-Lab-Toolkit/issues).

## Helpful information

Please include:

- project or dataset name and official URL;
- maintainer or owner;
- license and redistribution terms;
- supported platforms and versions;
- installation, restore, import, or access method;
- stable download or API source;
- checksum or signature options;
- the lab scenario it would demonstrate;
- expected validation and cleanup;
- whether data can contain personal, confidential, or regulated information.

## What inclusion means

A suggestion does not guarantee integration. Before automation, the project must pass architecture, security, license, provenance, maintenance, testability, and cost review.

When an integration is accepted, the goal is to keep upstream ownership visible and send readers to the authoritative project pages.
