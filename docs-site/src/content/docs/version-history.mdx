### Changed

- Corrected the Azure SQLVM Toolkit description to identify it as an unfinished predecessor and source of lessons.
- Aligned the assessment direction with Azure Arc and the migration component in SQL Server Management Studio.
- Clarified that architecture is committed design and roadmap entries are not shipped functionality.
- Reordered the roadmap so the managed, Azure VM, and containerized PostgreSQL
  paths, then Bicep, Terraform, and general Git/CI adapters, precede Fabric.
- Required a `secretStoreDecision` for every target and solution pack and a
  Bastion-first `administrativeAccessDecision` for every Azure VM.
- Separated repository engineering CI from the user-facing Git and pipeline
  capability.
- Marked the first S1 slice as current development behavior without claiming
  S1 completion or live deployment support.
- Preserved deterministic storage-account hash suffixes when long lab names
  require truncation.
- Required the build to import its pinned Pester, PSScriptAnalyzer, and
  powershell-yaml versions explicitly.

### Current limitations

- The module is an unreleased alpha and its command contract may change.
- Azure authentication, live `-WhatIf`, the PowerShell deployment engine,
  probes, local run state, and the teardown workflow are implemented and
  test-covered, but unreleased and never run against a live subscription.
- `Start-AzureDataLabDeployment` creates real Azure resources and
  `Start-AzureDataLabTeardown` deletes them.
- Guest execution remains preview-first and user-executed.
- Selected catalog integrity, marketplace image version, and default external
  secure input remain unresolved deployment blockers.
- No production security baseline.

The first implementation proof point is SQL Server on Azure VM from YAML through `-Plan`, `-WhatIf`, cost review, guarded deployment, probes, evidence, and confirmed teardown with cleanup proof.

Released entries will link to the matching Git tag and GitHub release. Published releases and release notes will define **Available** behavior; repository implementation and tests define **Current** behavior; accepted architecture defines **Committed design**; the roadmap records **Backlog**, **Exploratory**, and **Deferred** work.

The repository-level log is maintained in [`CHANGELOG.md`](https://github.com/kaysauter/Azure-Data-Lab-Toolkit/blob/main/CHANGELOG.md).
