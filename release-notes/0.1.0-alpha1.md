# Azure Data Lab Toolkit 0.1.0-alpha1

This prerelease starts the executable project. It covers the offline PowerShell
foundation and the Azure-facing lifecycle: sign-in, live resolution, `-WhatIf`
reconciliation, deployment, probes, and approval-gated teardown.

It is intended for contract review and local testing. Nothing in it has been
exercised against a live Azure subscription, so treat the Azure-facing commands
as unverified. `Start-AzureDataLabDeployment` creates real resources and
`Start-AzureDataLabTeardown` deletes them. Not for production use.

## Highlights

- Installable `AzureDataLabToolkit` module targeting PowerShell 7.6.
- Strict versioned YAML parsing and validation.
- Deterministic SQL VM plan creation with RFC 8785 serialization and SHA-256
  plan hashes.
- Idempotency keys bound to toolkit, contributor, engine, and catalog revision
  contracts as well as resolved user intent.
- Field-level precedence and provenance for defaults, template, YAML, derived
  values, and flags.
- Explicit Key Vault, Bastion, identity, network, disk protection, licensing,
  cost, sensitivity, ownership, idempotency, approval, and teardown decisions.
- Fixed secure SQL VM alpha profile with typed desired properties, Azure API
  versions, Trusted Launch, Secure Boot, vTPM, host encryption, private
  networking, managed identity, disk layout, and SQL IaaS least-privilege
  intent.
- Optional existing disk encryption set reference applied to every planned
  managed disk with fail-closed live compatibility requirements.
- Private Key Vault plan with RBAC, purge protection, private endpoint and DNS,
  plus an explicit external-secret or opt-in secure-generation gate.
- Azure Bastion Basic plan with a `/26` subnet, Standard static Bastion public
  IP, and no VM public IP.
- Metadata-only software and sample-data catalogs.
- Optional Azure Files backup-share planning with SMB OAuth, private endpoint
  and DNS, explicit VM identity authorization, no storage-account key, and an
  explicit blocker for the incomplete SMB OAuth guest client path.
- Manual SQL VM backup-restore solution pack that derives dbatools, separates
  offline script rendering from future staging, and keeps restore
  preview-first and replacement-disabled.
- Stable structured policy findings, deployment blockers, and plan-hash-bound
  acknowledgement requirements.
- Fail-closed resource-group reuse validation that binds the ARM ID to the
  configured subscription and resource-group name.
- Exact Azure type and subscription validation for reused Key Vault, Bastion,
  resource-group, and disk-encryption-set IDs, with a required Bastion reuse
  rationale.
- Scope-specific offline, Azure, and guest action preconditions and
  reconciliation sources.
- Collision-resistant storage-account and Key Vault truncation that preserves a
  deterministic 48-bit hash suffix scoped to normalized subscription and
  resource-group identities while keeping live collision checks fail-closed.
- JSON, Markdown, and standalone HTML plan export with hash verification and
  no-overwrite-by-default file handling. Readable exports include desired
  properties, dependencies, RBAC evidence, and exact approval requirements.
- Linux, Windows, and macOS pull-request checks.

## Commands

Offline, no Azure access and no mutation:

```powershell
Test-AzureDataLabConfiguration
New-AzureDataLabPlan
Export-AzureDataLabPlan
Find-AzureDataLabCatalogItem
Get-AzureDataLabSupportMatrix
Get-AzureDataLabTemplate
Start-AzureDataLabConfigurationWizard
New-AzureDataLabRun
Get-AzureDataLabRun
Get-AzureDataLabEvidence
Export-AzureDataLabEvidence
Test-AzureDataLabDeploymentConfiguration
Resolve-AzureDataLabPlan
```

Azure-facing. These authenticate, read live state, and in the case of
`Start-AzureDataLabDeployment` and `Start-AzureDataLabTeardown` create and
delete real resources:

```powershell
Connect-AzureDataLabAccount
Test-AzureDataLabAzureContext
Invoke-AzureDataLabPreflight
Test-AzureDataLabWhatIf
Start-AzureDataLabDeployment
Resume-AzureDataLabDeployment
Resolve-AzureDataLabDeployment
Test-AzureDataLabDeployment
Start-AzureDataLabTeardown
Resume-AzureDataLabTeardown
Resolve-AzureDataLabTeardown
```

- Exact imports of pinned Pester, PSScriptAnalyzer, and powershell-yaml build

## Not included

- Any verification against a live Azure subscription. Every Azure-facing
  command is implemented and unit-tested but has never been run for real.
- Guest setup, software installation, and database restore. The backup-restore
  solution pack renders scripts locally and stays preview-first and
  user-executed.
- Shutdown.
- A terminal UI, Bicep engine, or Terraform engine. `engine.type` accepts
  `bicep` and `terraform` in schema but neither is implemented, and plans fail
  closed with `implementationStatus: 'unavailable'`.
- An offline price cache. Cost estimation reaches `prices.azure.com`.
- Production support or a production security baseline.

Catalog artifacts intentionally remain blocked for deployment until their
integrity metadata is resolved. The marketplace image version and default
external secure input also remain blockers until future authenticated stages
resolve them.
